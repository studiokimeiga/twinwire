## Interpretation and limits

Delivery and latency follow the emulated network: roughly 64 snapshots/s on LAN/WS, 0.5% misses on good-5G RTC and 2% on congested RTC. Original per-cell mean p99 snapshot/input differences are at most 1.5 ms; render-error distributions broadly overlap. WebSocket stalls dominate congested p99 at about 258 ms for both stacks.

The original congested-RTC Twinwire cell has one 8.77 ms tick-p99 outlier. It is retained above; confirmation results must be considered alongside it. Bot combat is stochastic, so CPU and event-traffic differences cannot be assigned entirely to the transport. The confirmation table records whether the outlier repeats; it does not justify removing the original result.

The compact format reduces the fixed header from 22 to 12 bytes for the game's streams: 640 bytes/s per 64-Hz state stream before other traffic. Compared with the prior 1.2 run, measured Twinwire upload falls by roughly 0.6–0.9 KiB/s in the original matrix. It still costs about 0.8–1.1 KiB/s more than geckos/raw WS, because framing, probes and acknowledgements remain. Original Twinwire WebRTC download is 4.4–11.1 KiB/s lower; WebSocket download is about 0.5–1.1 KiB/s higher. Combat variation affects those download comparisons.

The A/B matrix predates the game lag-compensation fix. Its hit-agreement numbers describe the existing game defect and cannot establish post-fix accuracy. The separate deterministic 27-case regression and later integration checks validate that fix. The benchmark uses Node/libdatachannel clients and application-level emulation; it does not establish physical iPhone/cellular results or measured hosting bills.

The corrected harness pre-starts the intended bench mode and lets client bots escape when wedged (commit `d003915`). Earlier comparisons with mismatched room mode or wedged clients, including the “24% vs 10% CPU” claim, are excluded.
